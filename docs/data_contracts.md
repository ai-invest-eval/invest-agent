# 공통 데이터 계약

## 기준 문서와 적용 범위

- 채점·관문·QD·QN 기준은 [투자평가기준 v4](investment_criteria_v4.md)를 따른다. 원본 내용은 보존한다.
- 이 문서는 결측값·금액·날짜·단계의 구현 형식이다. 기준 문서의 “정보 없음”은 State에서는 `None`, 보고서에서는 표시 문구로 해석한다.
- 기준 문서의 프로필 필드·점수 키는 적용한다. 투자 이력·팀·제휴의 내부 필드는 이 문서와 schemas.py에 확정했다.

## 1. 결측값

- 예외: 개선본 v4가 명시한 `business_model` 미확인은 `unknown`이다. 일반 필드의 `None`과 구분하고 QD만 결측 2점 처리한다.
- 수집 결과의 미확인 값은 `None`(JSON에서는 `null`)으로 통일한다. `0`, `False`, 빈 문자열, `"정보 없음"`으로 대체하지 않는다.
- 목록도 미확인이면 `None`. 확인 결과 항목이 없으면 `[]`를 사용한다.
- 확인된 0은 `0`, 확인된 해당 없음은 `False`. 값의 부재와 사실상 부재를 구분한다.
- 프로필 수집 결과에서는 정의된 선택 필드도 키를 유지하고 미확인 값에 `None`을 넣는다. 초기 상태·테스트 fixture의 키 생략 허용과는 구분한다.
- `missing_fields`는 프로필 기준 점 경로를 사용한다. 예: `pre_money_valuation`, `team`, `gates.not_eligible`. 목록 내부는 `funding_history.0.amount`처럼 0부터 시작한다.
- `missing_fields=[]`는 기록할 미확인 필드가 없다는 뜻이다. State 제어용 빈 분석 문자열·빈 후보/평가 목록은 초기화 값이지 수집 데이터의 결측 표현이 아니다.
- 관문과 질문별 결측 판정은 v4를 따른다. “계약 없음”처럼 확인된 사실을 단순히 결측으로 처리하지 않는다.

## 2. 금액

계산용 숫자와 보고서용 표현을 분리한다. 투자금·선급금·기업가치의 금액 부분은 `MonetaryAmount`를 사용한다.

| 필드 | 의미 |
| --- | --- |
| `original_amount` | 원문 금액. 만·백만·억 등 배율을 풀어 기본 통화 단위로 저장 |
| `original_currency` | `KRW`, `USD`, `EUR` 등 대문자 통화 코드 |
| `krw_amount` | 원화 금액 또는 원화 환산 금액 |
| `usd_amount` | 달러 원문 금액 또는 달러 환산 금액 |
| `fx_date` | 환율 기준일. 고정 가정 환율은 `None` |
| `fx_source` | 환율 출처 또는 고정 가정 설명 |

- 국내 통화 표시: `N원`. 예: `1,400,000,000원`.
- 해외 통화 표시: `N원/M달러`. 예: `1,400,000,000원/1,000,000달러`.
- v4의 `USD_TO_KRW=1400`은 평가용 고정 가정이지 최신 환율이 아니다. USD 변환 시 `fx_source="투자평가기준 v4 고정 가정: 1 USD = 1,400 KRW"`, `fx_date=None`을 기록한다.
- USD 이외 통화는 확인 가능한 환율의 출처·기준일을 기록한다. 이를 확보하지 못하면 원문 금액을 보존하고 환산값은 `None`으로 둔다. 표시도 `원화 환산 미확인/달러 환산 미확인 (원문: 1,000,000 EUR)`처럼 명시한다.
- 환산값을 임의로 만들지 않는다. 금액 자체가 미확인이면 해당 금액 객체 전체가 `None`이다.
- 기준 문서에서 억 달러 단위를 쓰는 QD 등에는 계산 시 명시적으로 단위를 변환한다.
- 계약 총액과 선급금은 별도 항목이다. post-money를 pre-money로 바꾸지 않는다.

## 3. 날짜

- 확인된 정밀도까지만 ISO 8601 형태로 기록한다: 일까지 `YYYY-MM-DD`, 월까지 `YYYY-MM`, 연도만 `YYYY`.
- 미확인은 `None`. 알 수 없는 월·일을 `01`로 채우지 않는다.
- 이벤트·계약·평가 기준일과 자료 발행일을 혼동하지 않는다.
- `founded_year`, 출처의 `year`처럼 명시적으로 연도만 저장하는 기존 필드는 정수 또는 `None`을 유지한다.
- 부분 날짜만으로 기간·투자 공백을 확정할 수 없으면 추가 확인하거나 미확인으로 처리한다.

## 4. 투자 단계

- 국내 투자 시장 라운드는 `프리시드`, `시드`, `프리 시리즈 A`, `시리즈 A`, `시리즈 B`, `시리즈 C`, `시리즈 D` 등으로 표기한다.
- 해외 투자 시장 라운드는 접미사 `F`를 붙인다: `프리시드F`, `시드F`, `프리 시리즈 AF`, `시리즈 AF`, `시리즈 BF`, `시리즈 CF`, `시리즈 DF` 등.
- `F`는 이 프로젝트의 해외 구분 표식이다. 실제 Series F 라운드는 국내 `시리즈 F`, 해외 `시리즈 FF`로 구분한다.
- `stage_region`은 `domestic`/`foreign`/`None`, `stage_original`은 원문 단계명으로 보존한다. 기업 소재 국가만 보고 투자 시장을 추정하지 않는다.
- 단계만 확인됐지만 투자 시장이 미확인이면 접미사 없는 단계명과 `stage_region=None`을 사용한다. 이를 국내로 단정하지 않는다.
- 브리지·연장 라운드는 근거가 있을 때 해당 기본 단계로 정규화하고 원문을 보존한다. 단계가 밝혀지지 않은 브리지는 `브리지` 또는 `브리지F`로 기록하며 시리즈 단계는 추정하지 않는다.
- `상장`·`인수`는 해당 사건이 확인된 경우에만 사용한다. 기타 비표준 원문은 그대로 보존하고 `stage=None`으로 둘 수 있다.
- 적격성·QN 비교 시 `F` 유무로 단계의 높낮이를 판단하지 않는다. 기본 라운드와 투자 시장은 분리해서 확인한다.

## 5. 개발 단계

팀 공통 파이프라인 표기는 `개념`, `컴퓨터 예측`, `실험 검증`, `전임상`, `IND 신청`, `IND 승인`, `임상 1상`, `임상 1/2상`, `임상 2상`, `임상 2/3상`, `임상 3상`, `허가 신청`, `허가 승인`으로 둔다.

- `stage_original`에 원문을 보존하고, 확인한 근거에 맞는 단계만 기록한다. 미확인은 `None`.
- `Phase 1/2`, `Phase I/II`, `임상 1-2상`은 실제 복합 임상이라는 근거가 있으면 `임상 1/2상`으로 정규화한다. `Phase 2/3`·`임상 2-3상`도 `임상 2/3상`으로 보존한다. 단순 단계 범위·진입 계획은 복합 임상으로 단정하지 않는다.
- 복합 임상을 뒤 단계로 승격하거나 이전 단계 완료로 간주하지 않는다. 대표 파이프라인 선정에서 세부 진행 근거가 부족하면 억지로 우열을 만들지 않고 동률 시 공식 자료 첫 소개 규칙을 적용한다.
- `IND 신청`과 `IND 승인`은 다른 값이다. 계획·신청을 승인·임상 진입으로 승격하지 않는다.
- 임상 중단·실패는 성숙도 단계가 아니다. 원래 개발 단계는 유지하고 관문·근거에 별도로 기록한다.
- QH 점수는 단계명만으로 기계적으로 확정하지 않고 v4의 후보물질·실험·전임상·IND 승인 등 조건과 근거를 확인한다.
- 플랫폼 기업에 파이프라인이 확인되지 않았다고 임상 단계를 만들어 넣지 않는다. 자체 실험·공동 검증 근거는 기술 분석에 기록한다.

## 6. QN과 점수 전달

- QN은 같은 단계의 pre-money 기업가치 중앙값 대비 비율을 사용한다. v4 표: 0.7배 이하 5점, 0.7~1.0배 4점, 1.0~1.5배 3점, 1.5~2.5배 2점, 2.5배 초과 1점.
- 표 경계가 중첩되는 정확히 0.7·1.0·1.5배에서는 v4의 “두 칸 이상이면 낮은 점수”를 적용한다. 즉 각각 4·3·2점이다. 2.5배는 2점이다.
- 평가 대상과 비교기업은 같은 통화·단위로 계산하며 환율 가정을 기록한다. 비교기업 목록·기본 투자 단계·시장·기준시점·출처·중앙값 산출 근거를 질문별 근거에 남긴다.
- v4는 비교기업 중앙값 데이터 출처와 표본 범위를 지정하지 않는다. 중앙값을 임의로 만들지 않는다. 검증 가능한 값이 없으면 QN은 결측 3점으로 처리하고 결측 비중에 포함한다.
- 영역 키는 v4 그대로 `founder`, `market`, `product`, `moat`, `traction`, `deal`을 사용한다.
- v4 Judge 출력의 `reason`/`source`는 현재 공통 계약의 `rationale`/`references`로 매핑한다. 별도의 중복 필드는 만들지 않는다.
- `unconfirmed_gates`에는 미확인 리스크 관문 키만 기록한다. 해당 항목이 없으면 `[]`다.

- 보류 사유는 v4의 `관문(해당 항목)`, `자격 미확인`, `근거 부족`, `총점 미달`, `창업자 미달`을 사용하고 규칙 순서대로 판정한다. 별도 사유 코드 체계는 추가하지 않는다.
- 정렬은 총점 → 창업자 → 시장성 순이다. 판정·정렬은 반올림 전 값으로 수행한다. 보고서 표시만 담당자가 포맷하며 원본 점수를 덮어쓰지 않는다.
- 세 값이 모두 같으면 추가 평가 기준을 만들지 않는다. 보고서 담당자는 동점임을 드러내고, 표시 순서와 실제 우열 판단을 혼동하지 않는다.

## 7. REFERENCE

보고서 작성에 실제 활용한 자료만 기재한다. 검색 결과 전체·읽기만 한 자료·인덱스 전체는 포함하지 않는다. Agent 6은 본문 주장·수치·평가 설명에 사용한 출처를 추적해 최종 목록을 만든다. 같은 자료는 중복 기재하지 않는다.

유형별로 다음 형식을 사용한다.

- 기관 보고서: 발행기관(YYYY). *보고서명*. URL
- 학술 논문: 저자(YYYY). 논문제목. *학술지명*, 권(호), 페이지.
- 웹페이지: 기관명 또는 작성자(YYYY-MM-DD). *제목*. 사이트명, URL

Reference 필드는 다음과 연결한다.

| 유형 | 사용 필드 |
| --- | --- |
| 기관 보고서 | `issuer`, `year`, `title`, `url` |
| 학술 논문 | `authors`, `year`, `title`, `journal`, `volume`, `issue`, `pages` |
| 웹페이지 | `authors` 또는 `issuer`, `published_date`, `title`, `site_name`, `url` |

- `doc_type`은 `report`/`paper`/`web`이다. RAG 원문도 실제 문서 유형에 맞게 기록한다.
- `page`는 청크가 인용하는 원문 쪽수, `pages`는 논문의 전체 수록 페이지다. 서로 대체하지 않는다.
- 날짜는 확인된 날짜만 사용한다. 예시의 `2024-04015` 같은 오기는 형식 예시로 복제하지 않고 `YYYY-MM-DD`를 따른다.
- 서지정보가 없으면 `None`을 보존하고 표시 시 해당 값에 `미확인`을 사용한다. 원문에 없는 저자·날짜·권호·URL을 만들지 않는다.
- 같은 자료의 여러 청크는 목록에서 한 항목으로 합치되 원문 인용 쪽수는 보존한다. URL이 있으면 정규화 URL, 없으면 유형·제목·저자/기관·연도 등 서지정보를 대조한다.
- DOC_META는 해당 Reference 서지 필드를 보존한다. agent/topic 태그·청크 식별자는 검색 구현 담당자가 관리하고 서지정보와 혼동하지 않는다.

## 8. 에이전트 판단과 재검색

- Agent 1의 LLM이 출처 근거로 한영 별칭·동일 기업 여부를 판단한다. 대표 기업명을 확정하면 이후 노드와 평가 이력은 그 이름을 유지한다. candidate_id 추가는 현재 요구하지 않는다.
- 후보 없음 원인은 Agent 1이 확인한 탐색 근거로 판단한다. 빈 후보와 selected_startup=None 계약은 유지하고, 설명은 실제 사용 출처·실행 기록에 남긴다.
- Agent 6의 LLM은 후보 없음/통과 없음의 이유를 실제 탐색·평가 근거로 설명한다. 후보가 없는데 기업이나 추천 결과를 만들어내지 않는다.
- 그래프는 후보·평가 이력으로 반복/종료를 제어한다. 에이전트의 기업·근거 판단과 실행 제어를 구분한다.
- RAG 흐름: 질문 계획 → Dense/BM25 검색·RRF 병합 → **LLM이 청크에 분석 목적에 맞는 근거(수치·기준·사례)가 있는지 판단** → 충분하면 분석, 부족하면 검색어를 바꿔 최대 1회 재검색.
- 유사도 점수·청크 개수만으로 근거가 충분하다고 판정하지 않는다. 계속 부족하면 설계에 따른 웹 보완 또는 미확인·결측으로 처리한다.
- API/색인 오류는 근거 부족과 다른 기술적 실패다. 담당자가 오류 처리를 구현하고, 실패를 근거 없음이나 확인된 없음으로 위장하지 않는다.
- 검색 함수의 구체적 인터페이스·RRF 상수·필터는 3-A/3-B 담당자가 구현하면서 결정한다. 근거 적합성과 재검색 필요 여부는 LLM이 판단한다.

## 9. 사업 모델과 대표 시장 (개선본 v4)

- Agent 2만 `business_model`을 작성한다. 3-B·5번은 읽기만 하고 재분류하지 않는다.
- 권리 보유 자체 후보물질 1개 이상이면 `pipeline`. 혼합 사업도 동일하며 제약사 소유 공동개발 물질은 자체로 세지 않는다.
- 자체 후보물질 없이 제약사 대상 서비스·소프트웨어가 주 사업이면 `platform`. 재검색 후 확인 불가면 `unknown`.
- `business_model_basis={"reason": 근거 문장, "source": URL 또는 None}`을 기록하고 실제 근거 출처는 `references`(agent: profile)에 추가한다. URL 없는 RAG 원문 출처도 Reference에 보존한다.
- pipeline 대표 시장은 최선행 자체 파이프라인 적응증 1개(`lead_indication`). 동률이면 공식 자료 첫 소개 항목이다.
- platform 대표 시장은 공개 계약 최다 서비스 1개(`lead_service`). 확인 불가면 `AI 신약 개발 서비스` 전체다. 비해당 대표 시장 필드는 `None`.
- unknown이면 QD만 결측 2점·missing=True로 처리하고 나머지 질문은 정상 평가한다. 보고서에는 `사업 모델 미확인으로 정보 부족`을 표시한다.
- 치료 영역·상위 서비스 시장 수치를 대신 사용하면 각각 `치료 영역 기준`·`상위 시장 기준`을 명시한다.

## 10. 프로필 내부 구조 (확정)

| 항목 | 타입 / 필드 |
| --- | --- |
| 투자 이력 | `FundingRound`: date, stage, stage_region, stage_original, amount, investors, references |
| 투자자 | `Investor`: name, kind(financial/strategic/None), follow_on(bool/None) |
| 제휴 | `Partnership`: partner, kind, date, upfront_payment, references |
| 팀 | `TeamMember`: name, role, is_founder, full_time, degree, career, references |

- 내부 항목은 위 키를 유지하고 미확인 값은 None이다. 목록 전체 미확인은 None, 확인된 없음은 []다.
- 항목별 `references`에는 실제 근거의 Reference 객체를 넣는다. 웹 URL과 RAG 원문 쪽수를 모두 연결할 수 있다. `source_url`만 사용하는 방식은 폐기한다.
- 항목 안 Reference는 근거 연결용이다. State 업데이트의 최상위 references에는 새 출처만 한 번 추가하며, 중첩된 출처 목록이 reducer로 자동 누적되는 것은 아니다.
- `references=[]`는 연결할 근거가 없다는 뜻이며 해당 사실을 확인됐다고 주장할 수 없다. 결측 수집 값은 None을 유지한다.
- 금액은 MonetaryAmount를 재사용한다. 투자자는 해당 라운드의 후속 투자 여부를 기록하며 전체 이력으로 추측하지 않는다.
- 회사 수준 `upfront_payment`는 합계가 아니라 **양수 선급금이 확인된 계약의 대표 값**이다. 날짜가 확인된 계약 중 최신 계약을 선택하고, 최신이 동률이면 목록 순서를 사용한다. 날짜 확인된 양수 계약이 없으면 확인된 양수 계약 중 목록 첫 항목을 선택하며 날짜는 None을 유지한다.
- 해당 계약의 partner/date/references를 `upfront_payment_basis`에 남긴다. 양수 계약이 없고 모든 확인 대상 계약의 선급금 없음이 확인됐을 때만 0, 공개 조건이 불완전하면 None이다. 조건부 계약 총액을 대신 넣지 않는다.
- 회사 수준 기업가치는 최신 기준일이 확인된 pre-money 값을 보존한다. 날짜 미확인 값은 최신이라고 단정하지 않고 확인 가능한 값만 사용한다. `valuation_date`, `valuation_references`를 함께 기록한다. 값 자체를 확보하지 못하면 금액·날짜는 None, 출처는 확보된 비공개 근거 등이 있으면 연결하고 없으면 []다.

## 개발 전 추가 합의

현재 필수 추가 합의는 없다. [확정 계약 샘플](agreement_samples.md)로 각 담당자가 독립 개발한다. QN은 v4의 동일 단계 중앙값 대비 점수 구간·결측 3점 규칙을 적용한다. v4에 없는 기간 24개월·최소 3개 등은 강제하지 않는다. 비교 출처·조건은 5번 구현에서 검증하고 근거로 기록하며, 확인 불가면 결측 처리한다. 검색 세부 구현은 담당자의 TODO다.
